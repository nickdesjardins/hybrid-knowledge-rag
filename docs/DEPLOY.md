# Putting the showcase online, step by step

**Status (14 October 2026): online.** Steps 1 to 5 below were followed to put it there. They stay
here as the way to check it, change it, or rebuild it from scratch.

| What | Where | Address |
|---|---|---|
| The **project page**: recorded runs, the walkthrough, wakes the demo | GitHub Pages | <https://nickdesjardins.github.io/hybrid-knowledge-rag/> |
| The **live demo**: the API with its playground at `/` | Render (free web service, Docker) | <https://hybrid-retrieval-engine.onrender.com/> |
| The **database**: PostgreSQL with pgvector, already filled | Neon (created from Vercel) | not public |
| The **language model** | OpenRouter free models | not public |

The project page is the address to give to people. The live demo sleeps after 15 minutes without
a visit and needs about a minute to wake; the project page starts waking it as soon as it opens.

In this guide, **the service name** is the part of the demo's address between `https://` and
`.onrender.com`: here `hybrid-retrieval-engine`. If the service is ever re-created and Render
adds letters to it, use the new name wherever this guide shows that one.

## Where each secret goes

| Secret | This GitHub repository | Render | Your computer |
|---|---|---|---|
| OpenRouter key (starts with `sk-or-v1-`) | **never** | `OPENROUTER_API_KEY`, typed once in step 3 | `.env.local` |
| Neon connection string (`DATABASE_URL_UNPOOLED`, starts with `postgresql://`) | **never** | `DATABASE_URL`, typed once in step 3 | `.env.local` |
| Upload key (`API_KEY`) | **never** | generated by Render, nothing to type | not needed |

This repository needs **no secrets at all**: its two workflows (tests and the project page) use
none. Never paste a key into `render.yaml`, a commit, a chat or a terminal command.

## Step 1: put the code on GitHub (5 minutes) — done

The repository is <https://github.com/nickdesjardins/hybrid-knowledge-rag> (public), and this
folder is connected to it over SSH. To publish changes later, in PowerShell, in the project
folder:

```powershell
git add -A
```

Git may print lines saying that LF will be replaced by CRLF in some files. They are warnings
only: nothing failed and no file was damaged. Then check that no private file is about to be
published. The only line printed must be `.env.example`:

```powershell
git ls-files | Select-String -Pattern "env|Career"
```

If `.env.local`, `.env` or the career guide appears, stop and ask for help. Otherwise:

```powershell
git commit -m "Describe the change here"
```

```powershell
git push
```

If `git commit` says `nothing to commit, working tree clean`, or `git push` says
`Everything up-to-date`, nothing went wrong: there was nothing new to publish.

## Step 2: turn on GitHub Pages (5 minutes) — done

1. Open the repository, then **Settings** (top bar of the repository), then **Pages** in the
   left sidebar.
2. Under **Build and deployment > Source**, choose **GitHub Actions** (if it already says
   **GitHub Actions**, leave it). GitHub then suggests workflow templates: **ignore them**. The
   project already has its own (`.github/workflows/pages.yml`), and a template would add a second.
3. Open the **Actions** tab and look at the run called **Project page**. If it has a green
   check, go to 4. If it has a red cross with "Get Pages site failed", it started before
   step 2, which is harmless: open the run and click **Re-run jobs > Re-run all jobs**. (Or:
   **Project page** in the left list, **Run workflow**, branch `main`, **Run workflow**.)
4. When it is green, open <https://nickdesjardins.github.io/hybrid-knowledge-rag/>. The first
   time can take a few minutes. Yellow notes on this run that mention "Node.js 20" are warnings
   from GitHub, not failures.
5. The **Tests** run should be green too.

## Step 3: create the live demo on Render (20 minutes, mostly the first build) — done

Before you start, open `.env.local` in an editor (VS Code or Notepad). You will copy two values
from it. Copy only the part after the `=` sign, without quotes.

1. Go to <https://dashboard.render.com> and sign in (the same account as Phase 1 is fine).
2. Click **New > Blueprint**.
3. Find `hybrid-knowledge-rag` in the list and click **Connect**. If it is not in the list,
   Render's GitHub app is not allowed to see it yet: follow Render's link to configure GitHub
   access (or open <https://github.com/settings/installations>, **Render > Configure**), add
   `hybrid-knowledge-rag` under repository access, save, and come back.
4. **Blueprint name**: anything, for example `hybrid-knowledge-rag`. **Branch**: `main`. Leave
   **Blueprint path** empty.
5. Render lists what it will create: **one web service, `hybrid-retrieval-engine`, plan Free**.
   Check that it says Free. Render may ask for a card to verify the account (a $1 charge that
   is refunded). Do not add a card unless Render asks: without one, Render stops builds or
   pauses the service when a free limit runs out, instead of billing. With a card on the
   workspace (added now, or earlier for Phase 1), Render bills the extra instead: build minutes
   past 500 a month, and bandwidth past 5 GB at $0.15 per GB. If your workspace has a card,
   open **Workspace Settings > Build Pipeline > Set spend limit** and enter the lowest amount it
   accepts; bandwidth has no spend limit, so look at the **Billing** page now and then.
6. Fill in the two boxes Render shows. It asks for them **only this once**:
   - `OPENROUTER_API_KEY`: the value of `OPENROUTER_API_KEY` from `.env.local`. It starts with
     `sk-or-v1-`. If what you copied starts with `postgresql://`, it is the wrong line (the
     service would refuse to start).
   - `DATABASE_URL`: the value of **`DATABASE_URL_UNPOOLED`** from `.env.local`. It starts with
     `postgresql://` and has no `-pooler` in it. Not the line called `DATABASE_URL`.
7. Click **Deploy Blueprint**. Render shows the Blueprint's page while it creates the service.
   Open the service: click `hybrid-retrieval-engine` on that page (or on the dashboard's home
   page). It opens on its **Deploys** page (if not, click **Deploys** in the left menu). Click
   the deploy at the top to follow its build log. The first build takes about 10 minutes: it
   installs Python packages and downloads the two local models into the image. Wait until the
   deploy shows **Live**. If it shows **Failed**, the end of that log names the failing line;
   see [Troubleshooting](#troubleshooting). Later, messages from the running service are under
   **Logs**.
8. The service's address is at the top of the service page:
   `https://hybrid-retrieval-engine.onrender.com`.
9. Check it. Each of these opens in a browser:
   - <https://hybrid-retrieval-engine.onrender.com/livez> shows `"status":"alive"`;
   - <https://hybrid-retrieval-engine.onrender.com/health> shows `"status":"ok"` and
     `"database_connected":true`;
   - <https://hybrid-retrieval-engine.onrender.com/> opens the playground. Click a sample
     question, then **Ask**. The answer takes 10 to 40 seconds. Below the answer and its
     citations is a section titled **Walk through this answer**: click **Open all steps** and
     check that the six numbered steps open and show this answer's numbers.
10. Optional check that visitors are told apart (uses one free request). On your phone, on
    mobile data (not Wi-Fi), open the playground and click a sample question, but do not tap
    **Ask** yet. Then in PowerShell on your computer:

    ```powershell
    1..11 | ForEach-Object { try { $null = Invoke-RestMethod -Method Post -Uri "https://hybrid-retrieval-engine.onrender.com/api/v1/query" -ContentType "application/json" -Body '{"query":"limit check","filter_document_id":"00000000-0000-0000-0000-000000000000"}'; "$_ answered" } catch { $_.ErrorDetails.Message } }
    ```

    This sends 11 questions about a document that does not exist, so no model is called and
    each one comes back in a second or two. Lines 1 to 10 say `answered`; the 11th says "Too
    many questions from this address; please wait a minute." (If you asked a question in the
    last minute, the refusal comes one line earlier.) Right away, within the same minute, tap
    **Ask** on the phone: it must be answered. If the phone gets the same refusal, every
    visitor shares one budget. The demo is still safe; see [Troubleshooting](#troubleshooting).

If you typed a value wrong in step 6: service page > **Environment** > edit the value >
**Save and deploy**.

## Step 5: replace the OpenRouter key — done on 14 October; repeat whenever a key may have leaked

Phase 1 uses the same key, so both projects change together. Keep the old key until the new one
works everywhere.

1. On <https://openrouter.ai/keys>, click **Create Key**. Give it a name, and in **Credit
   limit** type `1` (one dollar; not 0, which blocks every request, free ones included). Free
   models cost nothing, so this limit never stops either demo; it only caps what the key could
   spend on paid models if it ever leaks. Copy the key. Then open
   <https://openrouter.ai/settings/credits>: if **Auto top-up** is on, turn it off.
2. Put the new key in this project's `.env.local`, then test it from the project folder (one or
   two free requests; it must print an answer):

   ```powershell
   .\.venv\Scripts\python.exe scripts\openrouter_smoke.py
   ```

3. Render, this service: **Environment** > `OPENROUTER_API_KEY` > edit > paste > **Save and
   deploy** (no rebuild needed). Wait until the new deploy shows **Live**: until then the old
   instance keeps answering with the old key. Then ask one question on the live demo.
4. Phase 1: update its `.env`; in its Render service, **Environment** > edit > **Save and
   deploy** (not **Save only**, which keeps the old key running), wait for **Live**, and try
   one extraction on its demo page. Then update its GitHub secret (**Settings > Secrets and
   variables > Actions > `OPENROUTER_API_KEY`**).
5. Only now, on <https://openrouter.ai/keys>, delete the old key.
6. If a demo fails after this, its Render service still has the old key: **Environment** >
   paste the key from `.env.local` > **Save and deploy**.

## Good to know about the free plans

- **Sleeping.** The demo sleeps after 15 minutes without a visit and takes about a minute to
  wake. The project page wakes it automatically.
- **Builds cost minutes.** Render gives 500 build minutes a month; one build of this image takes
  about 10, failed builds and **Clear build cache & deploy** included. A push that changes only
  `site/`, `docs/`, `README.md`, `.github/`, `tests/` or `scripts/` does not rebuild the
  service. Group other changes into fewer pushes.
- **Change settings in `render.yaml`, not in the dashboard.** For every setting that
  `render.yaml` lists with a value, edit the file and push: a later Blueprint sync can put the
  file's value back over a dashboard edit. The dashboard is the place only for
  `OPENROUTER_API_KEY`, `DATABASE_URL`, `API_KEY`, and settings the file does not list.
- **Fixed once created.** The region (Virginia, next to the Neon database in us-east-1) and the
  `onrender.com` address cannot be changed later.
- **Hours.** A workspace gets 750 free instance hours a month, shared by all its free services
  (Phase 1 included). Sleeping services use none. A service kept awake around the clock uses up
  to 744, and when the hours run out Render suspends every free service until the 1st.

## What protects the public demo

| Risk | Protection |
|---|---|
| Someone uploads documents | Uploads need `API_KEY`. The key and the size are checked before a byte of the upload is read. |
| Someone spends the day's free requests | Per visitor: 10 questions a minute and 60 a day. Everyone together: 20 a minute and 800 a day. And the service asks OpenRouter for the real count once a minute and stops at a reserve (50, or a fifth of the day's allowance if that is smaller). |
| Someone pretends to be many visitors | The address comes from `CF-Connecting-IP`, which Cloudflare (in front of every Render web service) overwrites; the left-most `X-Forwarded-For` entry, which a client can write, is never used. IPv6 visitors are grouped by their /64 network. |
| Someone floods the small instance | At most 4 questions are answered at once (more get 503 with `Retry-After`), questions are capped at 500 characters, every other request body at 32 KB, and the local models run one call at a time. |
| A typo makes the service call a paid model | `OPENROUTER_FREE_ONLY=true` refuses any model id that does not end in `:free`, at start-up. |
| The OpenRouter key leaks | With a $1 credit limit on the key and auto top-up off (step 5.1), it can spend at most $1 on paid models. Replace it as in step 5. |
| The database string is pasted into the key box | Start-up refuses a key that looks like a connection string, so the database password is never sent to OpenRouter. |
| A document tells the model what to answer | Passages are wrapped in tags with a random suffix per request, and declared untrusted. Every quote is checked against the stored text. |
| An error message leaks a key, a quota or SQL | Clients get the provider's name, "temporary" or "permanent", and an incident id; a database failure is a 503 with an incident id. Validation errors never echo the rejected input, and a bad setting is reported without its value. The detail stays in the log. |
| The corpus contains something private | The corpus is four fictional documents written for the demo (`scripts/make_demo_corpus.py`). |

Free endpoints may keep and train on what they are sent. Do not ingest real compliance documents
while the service runs on free models.

## Day-to-day

**Add a document to the live demo.** The key is `API_KEY` in Render's dashboard (service page >
**Environment**). Keep it out of command lines, which shells save in their history: read it into
a variable for the session.

In PowerShell (Windows), paste the key at the prompt; what you type at a `Read-Host` prompt is
not saved in the history:

```powershell
$env:DEMO_API_KEY = Read-Host "Upload key"
```

```powershell
curl.exe -X POST https://hybrid-retrieval-engine.onrender.com/api/v1/ingest -H "X-API-Key: $env:DEMO_API_KEY" -F "file=@my-document.pdf" -F "title=My Document"
```

In bash (macOS, Linux, Git Bash):

```bash
read -rs -p "Upload key: " DEMO_API_KEY
```

```bash
curl -X POST https://hybrid-retrieval-engine.onrender.com/api/v1/ingest -H "X-API-Key: $DEMO_API_KEY" -F "file=@my-document.pdf" -F "title=My Document"
```

Use `curl.exe`, not `curl`, in Windows PowerShell 5.1: there `curl` is an alias of another
command that does not take these options.

**Keep the demo awake (optional, part of the day only).** A free cron-job.org job can request
<https://hybrid-retrieval-engine.onrender.com/livez> every 10 minutes so visitors do not wait for
a cold start. Point it at `/livez` only: it never touches the database, so Neon still suspends
and its free compute allowance is not spent. Do not do this around the clock: one service awake
all day uses up to 744 of the workspace's 750 free hours, Phase 1 shares those hours, and when
they run out Render suspends both demos until the 1st. Limit the job to the hours people are
likely to look, for example every 10 minutes from 12:00 to 23:59 UTC (8:00 to 20:00 Eastern),
which is under 400 hours a month. Never do this for both services.

**Change the sample corpus**: edit `scripts/make_demo_corpus.py`, then

```powershell
.\.venv\Scripts\python.exe scripts\make_demo_corpus.py
```

```powershell
.\.venv\Scripts\python.exe scripts\record_runs.py --reseed
```

The second command replaces the sample documents in the database and records the runs again
(seven free requests). Commit `demo/` and `site/recorded/runs.json` and push.

**Run the showcase on your own machine.** This starts it in demo mode with the settings in
`.env.local`, without Docker. `render.yaml` is not read, so a few production settings differ:
for example `/docs` stays visible and `TOP_K_RETRIEVAL` is not 10.

```powershell
.\.venv\Scripts\python.exe scripts\run_local_demo.py
```

Open <http://127.0.0.1:8011/> in a browser; press Ctrl+C in PowerShell to stop it. It uses the
database and OpenRouter key from `.env.local`, so each question counts against the same free
allowance as the live demo.

**Check the local key and model chain** (one or two free requests). It reads `.env.local`, not
the values on Render:

```powershell
.\.venv\Scripts\python.exe scripts\openrouter_smoke.py
```

## Troubleshooting

| What you see | What it means | What to do |
|---|---|---|
| The repository is missing under **New > Blueprint** | Render's GitHub app cannot see it | GitHub > **Settings > Applications > Render > Configure** > add the repository. |
| Render asks for payment information | Usually a service that is not on the Free plan; sometimes an account check | Check that the service shows **Free** (`plan: free` in `render.yaml`). A verification charge of $1 is refunded. Once a card is on the workspace, Render bills extra build minutes and bandwidth instead of pausing: set the build spend limit and watch the **Billing** page (step 3.5). |
| Render: "Ran out of memory (used over 512MB)" | Both local models plus the service did not fit | In `render.yaml`, set `RERANK_PROVIDER` to `none` and push (frees about 100 MB; passages then keep their fusion order). |
| The build fails at the `RUN python -c "from fastembed ..."` line (service > **Deploys** > the failed deploy) | Hugging Face did not answer during the build, or its `xet` download tool failed | Use **Manual Deploy > Clear build cache & deploy**. If it fails again and the log mentions `xet`, open the `Dockerfile` and add this line on its own, just above the line that starts with `RUN python -c "from fastembed`: `ENV HF_HUB_DISABLE_XET=1`. Do not change the `ENV` block at the top. Then commit and push. |
| The deploy fails with "OPENROUTER_API_KEY does not look like an OpenRouter key" | Another line was pasted into the key box | Service > **Environment** > `OPENROUTER_API_KEY`: paste the `sk-or-v1-...` value, **Save and deploy**. |
| The deploy fails; the log shows "Database not ready" several times, or "must be a PostgreSQL connection string" | `DATABASE_URL` is empty (the service then tries a database on its own machine), copied incompletely or from the wrong line (wrong password or host), or not a connection string at all | Service > **Environment** > `DATABASE_URL`: paste the `DATABASE_URL_UNPOOLED` value from `.env.local`, then **Save and deploy**. If the value is right and the lines still appear, open the project in the Neon dashboard and check that it is active. |
| `/health` says `"status": "degraded"` with `generator.configured: false` | `OPENROUTER_API_KEY` is missing or empty | Service > **Environment**: set it, **Save and deploy**. |
| `/health` answers 503, or questions answer 503 "The database is unavailable" | The database cannot be reached. Right after a long idle period Neon may still be resuming. | Retry after a few seconds. If it persists, check `DATABASE_URL` and the Neon dashboard. The log line carries the incident id from the message. |
| Questions answer 503 "The demo is answering other questions" | Four questions were already being answered | Nothing to fix; the page shows when to retry. |
| `/livez` answers but `/` does not load | The service started but the playground is off | Check `PLAYGROUND_ENABLED` (true by default). |
| Start-up fails with `document_chunks.embedding is vector(384) but EMBEDDING_DIMENSIONS=...` | `EMBEDDING_DIMENSIONS` no longer says 384. The database column and the embedding model (bge-small) are both 384 wide, so no other value works. | Set it back to `"384"` where you changed it: in `render.yaml` (edit and push) or under service > **Environment** (**Save and deploy**). Do not empty or re-ingest the database. |
| Every question answers 502 "Upstream provider error (openrouter-auth)" | OpenRouter refused the key that Render has: it was mistyped, saved with **Save only**, or the old key was deleted before the new deploy was **Live**. `/health` still says `"ok"`, because it only checks that a key is set. | Run `scripts\openrouter_smoke.py` as in Day-to-day: it uses the key in `.env.local`. If it answers, paste that same value into service > **Environment** > `OPENROUTER_API_KEY`, **Save and deploy**, and wait for **Live**. OpenRouter shows a key only once: if no working key is left, create a new one (step 5). |
| Every question answers 502/503 "Upstream provider error (openrouter)" | Both free models failed, or both were withdrawn | In PowerShell, in the project folder, run `.\.venv\Scripts\python.exe scripts\openrouter_smoke.py`. For each model of the local chain (Render uses the same two unless `OPENROUTER_MODELS` is set in its **Environment**) it prints `listed` or `NOT LISTED (withdrawn?)`. It does not suggest replacements: pick ids that end in `:free` on openrouter.ai/models, set them in `OPENROUTER_MODELS` (service > **Environment**; `render.yaml` does not list it), then **Save and deploy**. |
| Questions answer 429 | A limit was reached; the message says which one and when it resets | "Too many questions from this address", "...reached its questions for today", "The demo is busy" and "The demo's daily question limit" come from `QUERY_RATE_LIMIT_PER_MINUTE`, `QUERY_DAILY_LIMIT_PER_CLIENT`, `QUERY_GLOBAL_LIMIT_PER_MINUTE` and `QUERY_DAILY_LIMIT` in `render.yaml`. "Today's free-model allowance is used up" is different: the OpenRouter account's free requests for the day are down to the last ones, which the demo leaves unused on purpose. The count covers the whole account (Phase 1, your local runs and the smoke script included). Wait until midnight UTC. |
| Your phone on mobile data is refused after your computer hit its limit (step 3.10) | Render did not pass `CF-Connecting-IP`, so all visitors share one budget | The demo stays safe (that is the stricter failure). Ask Render support which header carries the client address, and set it as `CLIENT_IP_HEADER` in `render.yaml`. |
| The project page says the demo "has not answered for three minutes" | The service is failing to start, or the link in `site/index.html` is mistyped (for example `https://` written twice; the **Tests** run is then red) | Open <https://hybrid-retrieval-engine.onrender.com/livez>. If it answers, fix the link as in step 4 and push. If it does not, read the service's **Deploys** and **Logs** on Render. |
| The project page still says "not online yet" | The page in your browser is an older copy, or the workflow has not finished | Wait for the **Project page** run to turn green, then reload the page. |
| An answer is slow (over a minute) | The free instance has a fraction of one CPU; the cross-encoder is the slow step | In `render.yaml`, lower `TOP_K_RETRIEVAL` from 10 to 6, or set `RERANK_PROVIDER` to `none`, and push. |
